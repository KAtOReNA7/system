# 03. 账单导入与数据治理

## 3.1 输入格式

历史账单记录粒度：

- 年月；
- 渠道ID；
- 文学库渠道名称；
- 授权分类；
- 我方作品ID；
- 作品名称；
- 实销金额；
- 参与分成实销金额；
- 不参与分成实销金额。

正式统计仅使用实销金额。

## 3.2 已知问题

- 同一文件中同一作品、同一渠道、同一月份重复记录；
- 金额为零或负数，通常是正确冲抵，必须保留并求和；
- 渠道主体更名但实际为同一公司；
- 分册作品多个ID实际属于一部完整作品；
- 后续账单不会重写历史，只会在未来月份通过冲抵或调整处理；
- 不同账单中出现相同作品并不等于重复。

## 3.3 导入流程

1. 上传单文件或多文件全量任务；
2. 计算文件指纹，阻止重复上传同一文件；
3. 后台分块解析；
4. 运行数据质量检查；
5. 汇总全部问题；
6. 生成清洗报告与问题文件；
7. 错误较少时逐项确认；错误过多时整份退回本地修改；
8. 修改后重新上传；
9. 所有关键问题解决后，整批事务写入；
10. 正式入库后生成账单导入批次对象；
11. 更新数据截止月份并触发相关作品数据更新。

## 3.4 阻断原则

- 所有疑似重复和其他数据问题在正式分析前必须处理。
- 基础数据问题未解决时不得进入评估。
- 原始金额、确认删除金额和正式入库金额必须严格对账。
- 任意关键步骤失败时整批回滚，不允许部分正式入库。

## 3.5 重复识别

初始规则基于：年月 + 渠道 + 作品ID + 作品名称 + 实销金额等字段组合，并结合真实账单总结其他异常模式。

- 明确重复可按确认规则自动删除；
- 疑似重复必须进入问题清单；
- 人工处理结果可沉淀为候选规则，但需Codex整理、验收后成为正式规则；
- 未确认疑似重复不得进入分析。

## 3.6 渠道治理

建立统一渠道对象与历史别名映射。原始账单保留原渠道名，同时关联统一渠道。渠道更名不拆分历史收入。

## 3.7 分册归并

- 系统发现疑似分册后提示运营补充或确认；
- 系统推荐主ID，运营确认；
- 合并后只作为一部标准作品处理；
- 其他ID不作为产品记录展示；
- 保存隐藏匹配映射，供后续账单自动归集；
- 名称、作者或业务形态冲突时阻断。

## 3.8 文件与批次留存

正式批次保存：文件名、指纹、覆盖年月、记录数、金额、清洗报告、导入/撤销状态和操作记录。原始账单文件不作为长期业务资产保存。

## 3.9 撤销

- 前期允许撤销正式导入；
- 撤销必须留下操作记录；
- 先识别实际受影响作品；
- 引用该批次的当前评估立即失效并自动重评；
- 重新导入按新批次处理；
- 撤销前创建恢复点。

## 3.10 验收重点

- 大文件后台运行，关闭页面后继续；
- 清洗报告完整；
- 原始合计、删除金额和正式合计严格对账；
- 批次事务原子性；
- 重复文件识别；
- 撤销和恢复后数据一致；
- 全量真实数据性能测试。

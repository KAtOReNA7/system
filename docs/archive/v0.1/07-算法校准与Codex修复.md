# 07. 算法校准与 Codex 修复

## 7.1 运营案例

覆盖新品和老品。案例以Word/PPT/PDF等形式上传，AI结构化后由运营确认。

新品案例包含当时输入、对标、预测、判断逻辑和后续实际结果。老品案例重点包含收入情况、生命周期和外部影响因素。

案例用于提炼规则，不作为简单相似案例推荐库。

## 7.2 规则流程

运营案例 → AI候选规则 → Codex综合多个案例和历史账单 → 正式规则版本 → 代表案例与验收用例 → 验收通过后自动启用。

前台不建设复杂规则编辑器。规则和提示词通过配置文件和Git版本控制管理。

## 7.3 AI与规则关系

AI理解规则并结合具体情况判断，不把规则作为不可变硬限制。案例数量不足时尤其需要防止过拟合。

## 7.4 评估稳定性

- 同一输入重复评估应基本稳定；
- 收入波动容忍范围通过回测确定；
- 高金额项目识别方式通过真实分布确定；
- 初判与复核不一致时进入自动裁决；
- 多次仍不稳定时标记评估异常。

## 7.5 不合理反馈

运营可对结果标记不合理，并用自然语言说明。结果仍可进入汇总和导出，但进入问题处理链路。系统稳定后可调整此策略。

## 7.6 问题聚合

AI自动合并相似反馈，形成问题组。状态：待处理、处理中、待验证、已解决。

问题组保存共性描述、代表案例、影响范围和相关模块。

## 7.7 Codex问题包

多个问题组可组成问题包。系统自动安排数量，运营直接导出。问题包包含代表案例和必要摘要，不默认包含全部原始账单明细。

根据系统模块化程度，问题包可给出建议修改模块或文件范围；自动生成验收测试。

## 7.8 修复与重评

- Codex写入代码、规则、提示词和版本信息；
- 代表案例优先重评；
- 通过后批量重评受影响作品；
- 成功结果逐个发布；
- 失败作品保持失效或异常；
- 支持整批回滚；
- 生成前台简版重评报告和Codex详细报告。

## 7.9 版本影响范围

Codex判断新规则实际影响范围，不全库重评。影响范围可基于评估类型、来源、分类、生命周期、对标方法、收入规模和旧规则版本。

## 7.10 历史结果

正式结果不得无痕覆盖。当前有效、历史版本、已失效和评估异常分别保存。错误评估不回溯修改已发布年度目标，只更新后续滚动预计并在复盘中记录。

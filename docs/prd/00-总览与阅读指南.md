## 0.1 项目名称

**有声书产品收入评估与年度目标系统**

## 0.2 系统定位

本系统是面向有声书运营负责人和一线运营的内部分析平台，核心任务不是替代财务系统，也不是自动决定业务动作，而是：

- 清洗并治理历史实销账单；
- 形成稳定的标准作品、渠道、分类和标签主数据；
- 对已产生实销的作品进行生命周期识别、剩余版权期收入预测和评级；
- 对上线前选题进行首年与五年收入预测和新品评级；
- 通过运营案例、历史回测和不合理反馈持续校准算法；
- 在老品预测稳定后，生成下一自然年度实销目标并跟踪实际完成。

系统输出是“建议 + 可执行标准”，但不设置机械的“是否开发”“是否继续运营”二元结论。运营基于评级、预测、风险和判断依据自行决策。

## 0.3 数据边界

- 财务系统导出的原始账单，是金额事实的最终权威来源。
- 本系统是重复清洗、渠道统一、作品归并、分类标签、评估、预测和年度目标的权威来源。
- 新品选题在未产生实销、未补充作品 ID 前，与老品库、年度目标及其他业务模块无关。
- 年度目标只基于制定目标时已经产生实销、完成正式老品评估的作品。

## 0.4 核心对象

- 标准作品：数字主体 ID，是老品库、评估、预测和年度目标的核心对象。
- 业务形态：有声版权与有声成品，分别保存收入构成，但共享原作级评级、版权期限和产品状态。
- 选题记录：没有运营可见项目 ID；产生实销后通过作品 ID 与标准作品建立唯一正式关联。
- 新品评估与老品评估：两个独立业务对象，共用版本、快照、AI复核、反馈和修复基础能力。
- 作者、渠道、主分类、辅助标签、特殊标签：独立数据对象。

## 0.6 使用原则

1. 后续结论覆盖早期结论，以 `02-冲突检查与覆盖记录.md` 为准。
2. 待数据验证项不得在代码中写死为未经验证的阈值。
3. 页面方案是信息架构要求，不是最终视觉规范；正式开发前应使用产品设计插件重新设计。
4. 正式评估必须保存完整结构化输入快照和技术版本。
5. 正式结果不得无痕覆盖；失效、历史、重评和修复必须可追溯。

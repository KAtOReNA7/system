# 08. 任务、通知、导出与监控

## 8.1 任务原则

- 页面关闭后任务继续；
- 任务显示进度和预计完成时间；
- 系统通过历史任务自回归优化时间预估；
- 同一作品相同输入和算法版本的重复任务自动合并或删除后发起；
- 运行中重复任务按既定规则处理；
- 取消后删除中间数据，保持状态简单；
- 普通任务记录保留期限由实际数据规模确定。

## 8.2 任务状态

排队中、评估中、复核中、已完成、已取消、任务失败。

## 8.3 重试

根据失败类型决定：网络、限流、临时服务故障自动重试；数据缺失、归并冲突、区间不收敛等确定性问题不重复浪费调用。

## 8.4 批量任务

- 系统动态控制并发；
- 代表案例优先；
- 单个失败不阻断其他作品；
- 批量任务邮件只发送一次汇总；
- 成功、失败、跳过和变化摘要进入报告。

## 8.5 通知

通知中心覆盖：任务完成、自动重评结果、回测异常、重要预计变化、问题组状态和系统异常。

邮件用于：批量任务完成、严重故障、备份失败、数据可能受损、大范围重评失败等。普通单个失败不发送灾难通知。

## 8.6 导出

- 评估结果支持Excel和可复制文字报告；
- 文字报告支持一键复制；
- 年度目标默认导出当前版本；历史版本需选择后单独导出；
- 导出字段权限第一阶段不限制；
- 报告和Excel口径必须与页面一致。

## 8.7 监控

覆盖任务队列、AI成功率、耗时、账单异常、数据库和存储、接口性能、邮件、自动重评、备份和恢复验证。

不建设运营运维驾驶舱，监控主要供系统和Codex排查。

## 8.8 健康检查

自动检查核心一致性：批次金额、ID关联、当前有效评估唯一性、选题一对一关联、年度目标汇总、实际实销与账单一致、备份和卡死任务。

低频孤立文件、旧日志和索引问题由Codex按需维护。

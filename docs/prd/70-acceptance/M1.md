# M1 数据基础验收

**状态：FROZEN**

## 验收前提

- 使用完整或接近完整的真实账单副本；
- 覆盖重复记录、负数冲抵、渠道更名和分册归并样本；
- 所有验收用例映射稳定需求编号；
- 不使用人工构造的整齐数据代替真实数据验收。

## 验收用例

### AT-M1-001 字段与金额口径

导入仅含当前七个业务字段的账单，系统只以实销金额统计；零值和负值原样保留。

### AT-M1-002 文件与批次

普通上传入口识别并阻止相同文件指纹；不同文件形成不同批次；多文件全量任务可以汇总进度。

### AT-M1-003 业务原子性

大型账单分块处理时，正式库和业务页面不得看到部分导入结果；失败后正式数据保持不变。

### AT-M1-004 严格对账

原始实销合计减去已确认删除金额必须等于正式入库金额；不一致时阻断。

### AT-M1-005 文件留存

正式导入后可查询文件元数据、指纹、金额和清洗报告；原始文件按规则删除。

### AT-M1-006 数据截止月份

新增、撤销批次后，系统分别正确更新账单最大月份和最新已确认完整月份。若当前有效批次覆盖到 `2026-05`，但人工确认 `2026-05` 为不完整账单月份，则收入事实继续保存，账单最大月份为 `2026-05`，正式评估数据截止月份仍为 `2026-04`。

### AT-M1-007 撤销与重新导入

撤销后只移除该批次影响，相关派生数据正确重算，并生成受影响标准作品集合及可供后续模块消费的幂等影响记录。相同指纹文件只能从已撤销批次发起受控重新导入；新批次引用旧批次，完整重新解析和校验，不继承旧问题处理决定，且不重复写入。M1 不验收评估失效或自动重评。

### AT-M1-010 数据问题阻断

未解决疑似重复或冲突时不得正式导入，也不得进入评估。

### AT-M1-011 重复与冲抵

明确重复按确认规则删除；合法零值和负值不被误删。

### AT-M1-012 本地修改流程

问题过多时可生成问题文件和清洗报告，重新上传后完整重新校验。

### AT-M1-020 标准作品 ID

`12345` 与 `Y12345`正确归属标准作品`12345`，且不生成新的运营业务编号。

### AT-M1-021 业务形态

两种业务形态收入分别汇总，但共享标准作品状态和版权期限。

### AT-M1-022 标准作品上线时间

不同业务形态首次正数实销月份不同时，标准作品上线时间取最早月份。零金额和负金额不作为首次实销；同月存在正数和负数时，只要存在正数记录，该月可以作为上线月份。从未出现正数实销的标准作品，上线时间留空并进入异常确认。

### AT-M1-023 业务形态首次实销月份

两种业务形态分别保留自己的首次正数实销月份。零金额和负金额不作为首次实销；同月存在正数和负数时，只要存在正数记录，该月可以作为该业务形态首次实销月份。从未出现正数实销的业务形态，首次实销月份留空并进入异常确认。

### AT-M1-024 分册归并

归并后前台只显示主标准作品；旧 ID 再次出现自动映射，冲突时阻断。

### AT-M1-025 常规 ID 唯一性

正常业务中，同一标准作品的一种业务形态只能存在一个常规原始财务 ID；额外 ID 只有经确认后才能作为历史分册隐藏映射存在。

### AT-M1-026 标准作品状态

标准作品状态只允许已上架、疑似下架、已下架和重新上架；业务形态不保存独立产品状态。

### AT-M1-027 标准作品基础信息

进入后续评估前，标准作品名称、作者、一级至三级主分类、版权开始日期和版权到期日期均完整有效。数字版权台账中的 `签订日期` 作为版权开始日期，`到期时间` 作为版权到期日期；台账未覆盖或日期缺失时进入基础信息补全。账单派生的 ID、上线时间、首次实销月份和文件创建时间不得覆盖或推算版权日期。

### AT-M1-028 基础信息补全表

系统可导出待补全表，运营本地填写后上传。上传文件经过临时解析、字段校验和问题报告；存在阻断问题时不应用任何变更，全部通过后整批应用并保留变更记录，失败可恢复且不留下部分修改。

### AT-M1-029 作者与作者别名

标准作品正确引用作者对象；作者别名保留来源和确认记录；同一规范化别名出现多作者歧义或同名作者无法确认时阻断，不自动错误归并。

### AT-M1-030 渠道更名

历史别名正确汇总至统一渠道，原始名称仍可追溯。

### AT-M1-031 共享版权期限与反例阻断

两种业务形态共享标准作品层版权期限；真实数据出现纯数字和 `Y` 业务形态期限反例，或同一标准作品存在多组不同 `签订日期` / `到期时间` 时，阻断并生成业务确认项。系统不自动扩展为业务形态级版权期限，不根据出现频率、金额或日期长短选择某一组期限，确认结果必须可版本追溯。

### AT-M1-040 分类路径

每部作品只有一条完整三级路径，出版物与网文分类体系隔离。

### AT-M1-041 标签库

辅助标签与特殊属性标签分开管理，版本变更可追溯。

### AT-M1-050 后台任务

页面关闭后任务继续；任务状态和业务阶段可查询；取消、失败和重试语义正确。

### AT-M1-051 AI 不降级

指定模型不可用时任务失败或等待原模型重试，不调用较弱模型。

### AT-M1-052 备份恢复

关键操作前恢复点可用；恢复后数据一致性检查通过且不会重复导入或重复触发任务。

## 后续里程碑验收建议（非 M1 正式规则）

- M2 建议验证：评估模块能否幂等消费 M1 生成的批次影响记录，并按后续确认的规则处理受影响正式评估。
- M4 建议验证：校准与修复模块能否基于已确认的失效结果和影响记录进入自动重评闭环。

以上仅为后续验收建议，不新增评估失效或自动重评的业务规则；正式行为需在对应里程碑另行确认。

## M1 完成标准

- 全量真实账单完成处理并严格对账；
- 标准作品、渠道、分类和标签主数据可以支撑 M2；
- 无阻断性缺陷；
- 业务原子性、撤销、恢复和幂等通过验证；
- 文档、需求追踪和验收记录全部更新。

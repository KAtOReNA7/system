# 10. 技术与发布约束

## 10.1 环境

- 正式数据库与开发测试环境隔离；
- 开发和测试可共用环境；
- 测试使用按需创建的完整真实数据副本；
- 测试结果不得回写正式环境；
- 测试邮件、凭证和任务必须隔离。

## 10.2 配置

AI模型、API地址、提示词、规则、换算公式、任务并发和重试参数通过技术配置文件管理并纳入Git。

## 10.3 AI模型

指定模型不可用时不降级。临时错误重试原模型，超限后进入异常清单。

## 10.4 事务与幂等

- 账单正式导入整批事务；
- 关键写入必须幂等；
- 恢复后识别已完成、执行中和未开始任务，避免重复账单和重复通知；
- 重评发布以单作品独立结果为单位，批次保留整体回滚能力。

## 10.5 备份与恢复

- 数据库每日自动备份；
- 关键操作前创建恢复点；
- 定期验证备份可恢复；
- 备份不只保存在同一机器或卷；
- 恢复后运行核心一致性检查。

关键操作包括：账单导入/撤销、归并、规则启用、批量重评、批量分类标签修改、年度目标重要调整。

## 10.6 发布

Codex修改 → Git提交 → 自动测试 → 数据一致性检查 → 代表案例 → 真实数据测试 → 运营验收 → 正式部署 → 健康检查。

部署失败时按影响范围自动回滚代码、配置、规则和数据库迁移，并收集故障包供Codex修复。

## 10.7 性能

最终指标使用全量真实数据制定。初始测试参考：常规列表与筛选约2秒，普通汇总约5秒，复杂汇总和大范围导出约10秒或后台任务。

## 10.8 文件

- 账单支持单大文件或多文件全量任务；
- 分块解析，整批提交；
- 选题文档支持自动拆分和合并结果；
- 超出实际处理能力时才提示运营拆分；
- 文件损坏、加密或无法读取时阻断。

## 10.9 数据删除

- 未关联老品的选题可以完整删除；
- 已关联标准作品的选题禁止删除；
- 正式老品永不删除，只修改状态和数据关系；
- 收入事实通过撤销账单批次修正，不直接删除作品。

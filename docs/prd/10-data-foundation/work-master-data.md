# 标准作品、业务形态与分册归并

**状态：FROZEN**

## REQ-WORK-001 标准作品 ID

标准作品 ID 使用原始财务作品 ID 的数字主体。系统可拥有不可见技术主键，但不得生成新的运营业务编号。

## REQ-WORK-002 业务形态

- 纯数字原始 ID：有声版权。
- `Y+数字主体`：有声成品。
- 标准作品下分别建立业务形态记录并分别汇总收入。
- 业务形态不拥有独立产品状态或独立版权期限。

## REQ-WORK-003 标准作品上线时间

标准作品上线时间取该标准作品两种业务形态首次正数实销月份中的最早值。

首次正数实销月份按以下规则计算：

- 零金额和负金额记录不作为首次实销；
- 同月同时存在正数和负数记录时，只要存在正数实销记录，该月可以作为首次实销月份；
- 从未出现正数实销的标准作品，标准作品上线时间留空并进入异常确认。

该时间用于：

- 老品库统一上线时间；
- 标准作品生命周期起点；
- 年度目标“新品实销”识别；
- 同类作品首年、三年、五年周期计算。

后来新增另一业务形态，不再次将该标准作品识别为新品。

## REQ-WORK-004 业务形态首次实销月份

有声版权和有声成品分别保留各自的首次正数实销月份，用于收入结构分析和业务形态演变说明，但不替代标准作品上线时间。

业务形态首次实销月份同样只取首次出现正数实销记录的月份。零金额和负金额不作为首次实销；同月存在正数和负数时，只要存在正数记录，该月可以作为该业务形态的首次实销月份。从未出现正数实销的业务形态，首次实销月份留空并进入异常确认。

## REQ-WORK-005 分册归并

- 系统根据名称、作者、分类、版权期限和前缀推荐主标准作品 ID，运营确认。
- 其他分册 ID 不再作为独立产品记录展示。
- 必须保存隐藏映射 `历史分册 ID → 标准作品 ID`，仅用于后续账单自动匹配和冲突检查。
- 历史 ID 再次出现时自动映射；名称、作者或业务形态明显冲突时阻断。

## REQ-WORK-006 常规 ID 唯一性

正常业务中，一种业务形态只对应一个原始财务 ID。多个不同数字 ID 仅作为历史分册异常在清洗阶段处理，不作为常规多 ID 业务结构。

## REQ-WORK-007 标准作品状态

标准作品状态仅保留：已上架、疑似下架、已下架、重新上架。业务形态不单独保存状态。

## REQ-WORK-008 标准作品基础信息

标准作品正式进入后续评估前，至少必须具备：

- 标准作品名称；
- 作者；
- 一级、二级、三级主分类；
- 版权开始日期；
- 版权到期日期。

标准作品 ID、标准作品上线时间和业务形态首次实销月份由账单及映射规则形成，不由基础信息补全表覆盖。

版权开始日期和版权到期日期的权威来源优先级为：

1. 已确认数字版权台账：`签订日期` 作为版权开始日期，`到期时间` 作为版权到期日期；
2. 运营补全文件；
3. 后续正式基础信息版本。

系统不得根据作品上线时间、首次实销月份、文件创建时间或其他账单派生时间推算版权开始日期。台账未覆盖或日期缺失的标准作品继续进入基础信息补全；同一标准作品存在多组不同 `签订日期` 或 `到期时间` 时，进入版权期限冲突确认，不自动选择。

## REQ-WORK-009 基础信息补全表

- 系统基于当前标准作品和基础信息状态导出待补全表。
- 运营在本地填写后上传补全文件。
- 系统必须临时解析并执行字段、引用、日期和整批一致性校验。
- 存在问题时生成问题报告，不允许部分正式应用。
- 全部关键校验通过后整批正式应用，并保存变更记录。
- 正式应用前创建恢复点；失败时正式基础信息保持不变。

## REQ-WORK-010 作者与作者别名

- 作者是独立主数据对象，标准作品引用作者对象。
- 作者别名必须保留来源和确认记录。
- 一个当前有效的规范化作者别名不得静默指向多个作者；存在歧义时阻断并要求确认。
- 同名作者不能仅凭名称自动归并。

## REQ-WORK-011 共享版权期限与反例阻断

当前业务规则仍为两种业务形态共享标准作品层的版权期限。数字版权台账中的 `签订日期` 和 `到期时间` 分别作为标准作品层版权开始日期和版权到期日期的已确认候选来源。M1 使用真实数据进行一致性验证；发现纯数字和 `Y` 业务形态期限反例，或同一标准作品存在多组不同版权期限时，阻断并生成业务确认项，不由开发自行扩展模型或自动选择某一组期限。

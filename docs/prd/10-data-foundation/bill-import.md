# 账单导入、批次与撤销

**状态：FROZEN**

## REQ-DATA-IMPORT-001 账单字段

当前正式账单每条记录仅包含以下业务字段：

- 年月；
- 渠道 ID；
- 文学库渠道名称；
- 授权分类；
- 我方作品 ID；
- 作品名称；
- 实销金额。

`实销金额`是唯一金额字段，也是收入统计、预测、评级、年度目标和对账的唯一金额口径。零值与负值必须原样保留。

## REQ-DATA-IMPORT-002 文件与批次

- 每个上传文件必须具有文件指纹和文件元数据。
- 普通上传入口必须阻止相同文件指纹重复上传。
- 一份通过校验并正式导入的文件形成一个账单导入批次。
- 多文件首次全量任务可以包含多个批次，但必须具有上层任务用于汇总进度和整体结果。

## REQ-DATA-IMPORT-003 处理与业务原子性

- 大文件允许后台分块解析、校验并写入临时区域。
- 正式导入要求业务原子性：外部不得看到部分正式结果。
- 只有全部关键校验通过后，批次才切换为正式有效。
- 具体实现不得被限定为一个持续时间过长的数据库事务，可使用临时表、批次状态切换或等价机制。

## REQ-DATA-IMPORT-004 严格对账

必须满足：

`原始账单实销合计 - 已确认删除金额 = 正式导入实销合计`

不得接受无依据尾差，不得人工输入调整金额凑平。

## REQ-DATA-IMPORT-005 文件留存

- 正式导入后保留文件名、指纹、覆盖月份、记录数、实销合计、清洗报告、导入状态和操作记录。
- 原始账单文件不作为长期业务资产保存。
- 删除失败必须记录并进入技术异常，不影响已确认的正式数据内容。

## REQ-DATA-IMPORT-006 数据截止月份

系统必须区分两个逻辑月份：

- **账单最大月份**：根据所有当前有效正式批次所覆盖的最大账单月份计算。被撤销批次不得继续影响账单最大月份。
- **最新已确认完整月份**：由人工完整性确认记录确定，作为正式评估、老品/新品判断和后续统计口径的数据截止月份。

当前运营确认：`2026-05` 为不完整账单月份，当前最新已确认完整月份为 `2026-04`。

不完整月份的收入事实必须继续保存、参与原始事实追溯和后续补齐，但不得作为正式评估的数据截止月份。系统需要保留月份完整状态、确认人、确认时间、确认依据和生效记录。暂不设计物理表。

## REQ-DATA-IMPORT-007 撤销与重新导入

- 撤销前创建恢复点。
- 撤销只影响该批次引入的正式收入和关联变化。
- M1 完成批次撤销、相关派生数据重算、受影响标准作品集合生成，并写入可供后续模块消费的幂等影响记录。
- M1 不负责评估失效或自动重评；相关行为由后续评估与校准里程碑另行确认和验收。
- 相同指纹文件仅允许从对应的已撤销批次发起受控重新导入，普通上传入口继续阻止。
- 受控重新导入必须形成新批次并引用旧批次，不复用旧批次状态。
- 受控重新导入必须完整重新解析和校验，不继承旧批次的数据问题处理决定。
- 撤销和重新导入必须具有幂等保护。

## 1. v0.3 变更项

v0.3 在 v0.2 可实现性结论上新增或修正以下 DDL 相关点：

1. 新增 `system_state` 控制表；
2. 表数量口径调整为 47 张 M1 业务表 + 1 张控制表 = 48 张物理表；
3. `historical_volume_mapping` 同一 `mapping_version_id` 内按完整 `historical_raw_work_id` 唯一，唯一键不包含 `business_form`；
4. `raw_work_id_mapping` 与 `historical_volume_mapping` 之间的完整原始 ID 互斥由 deferred constraint trigger 实现；
5. `business_form` 由完整原始作品 ID 的单一权威解析函数派生，不由授权分类推断；
6. 基础信息版本改为“基础信息作用域全量快照”，不要求每个 `standard_work` 都已进入 active 基础信息版本；
7. 初始化阶段允许 0 个 active 映射/基础信息/分类/标签版本；`operational` 阶段要求四类对象各恰好 1 个 active；
8. 迁移工具冻结为 Flyway SQL-only，正式迁移继续 forward-only。

## 2. PostgreSQL 可实现性结论

| 项目 | 结论 |
|---|---|
| `system_state` 单行控制表 | 可通过 `smallint PK` + `CHECK(id=1)` 实现 |
| 最多一个 active 版本 | 继续使用部分唯一索引 `WHERE status='active'` |
| 初始化允许 0 active | 由读取 `system_state` 的 deferred constraint trigger 判断生命周期，不需要禁用约束 |
| 运行期至少一个 active | 在 `operational` 状态下，提交前触发器校验映射、基础信息、分类 release、标签 release 各 1 个 active |
| 跨表原始 ID 互斥 | deferred constraint trigger 在提交前锁定对应 `mapping_version` 行并检查两张映射表并集 |
| 历史分册唯一性 | `UNIQUE(mapping_version_id, historical_raw_work_id)` 可直接创建，不受 NULL 语义影响 |
| ID 解析函数 | 可用不可变/稳定 SQL 或 PL/pgSQL 函数集中实现；约束触发器调用同一函数 |
| 基础信息缺口视图 | 以 `standard_work` 左连接 active 基础信息版本可实现，缺失作品不会被过滤掉 |

## 3. 需要隔离验证的最高风险点

1. `12345` 与 `Y12345` 在同一映射版本内可分别作为不同完整原始 ID 存在，并映射到同一标准作品 ID。
2. 同一完整原始 ID 不得同时存在于常规映射和历史分册映射。
3. `historical_volume_mapping` 中同一完整历史原始 ID 即使写入不同 `business_form` 也必须被拒绝。
4. 授权分类变化不得改变 `derive_business_form(raw_work_id)` 的结果。
5. `ready_for_bill_activation` 到 `operational` 的首版切换不得通过人工禁用约束完成。
6. 基础信息缺口视图必须返回尚未进入基础信息版本的 `standard_work`。

## 4. 审查结论

v0.3 未引入 PostgreSQL 16 无法表达的约束。新增内容需要在非正式隔离实例中真实创建并验证触发器行为后，才允许固化为正式迁移文件。

本补充不替代正式 DDL 验证；它只说明 v0.3 相对 v0.2 的模型变化在 PostgreSQL 16 中具备可实现路径。

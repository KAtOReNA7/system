## 1. 本次增量修订范围

v0.3 继承 v0.2 的不可变收入事实、版本化映射投影、基础信息补全、撤销和受控重新导入设计，仅覆盖以下已由真实数据和运营/财务确认解除待定的规则：

1. 完整数据截止月份；
2. 首次实销月份金额符号；
3. 金额精度语义和物理精度候选；
4. 同一作品 ID 多名称、多授权分类和台账冲突组的确认单位；
5. 数字版权台账对 M1 基础信息需求的覆盖结论；
6. 版权开始日期已确认语义；
7. 物理模型设计、首次正式数据迁移和 M2 正式评估的分层门槛。

本文件不新增业务规则阈值，不自动启用清洗、归并、渠道映射或产品状态判断规则。

## 2. 完整数据截止月份

### 2.1 已确认规则

运营确认：

- `2026-05` 是不完整账单月份；
- 当前最新已确认完整月份为 `2026-04`；
- 不完整月份的收入事实继续保存，但不得作为正式评估的数据截止月份。

### 2.2 逻辑字段

M1 逻辑模型必须区分：

| 逻辑字段 | 含义 | 权威来源 |
|---|---|---|
| `bill_max_month` | 当前有效正式批次覆盖到的最大账单月份 | 有效批次的覆盖月份集合 |
| `latest_confirmed_complete_month` | 可用于正式评估的数据截止月份 | 人工月份完整性确认记录 |
| `month_completeness_status` | 月份完整状态，至少区分未确认、已确认完整、已确认不完整 | 人工确认记录 |
| `month_completeness_confirmed_by` | 确认人 | 人工确认记录 |
| `month_completeness_confirmed_at` | 确认时间 | 人工确认记录 |
| `month_completeness_basis` | 确认依据或备注 | 人工确认记录 |

以上为逻辑字段，不在本阶段设计物理表。

### 2.3 重算触发

- 批次发布、撤销、恢复后，重算 `bill_max_month`；
- 月份完整性人工确认变更后，重算 `latest_confirmed_complete_month`；
- 正式评估、年度目标、新品/老品识别使用 `latest_confirmed_complete_month`，不得直接使用 `bill_max_month`；
- 收入事实查询、对账和后续补齐仍可看到不完整月份的原始收入事实。

对应：`REQ-DATA-IMPORT-006`、`AT-M1-006`。

## 3. 首次实销月份

### 3.1 已确认规则

标准作品和业务形态的首次实销月份，均取首次出现正数实销记录的月份。

规则边界：

- 零金额记录不作为首次实销；
- 负金额记录不作为首次实销；
- 同月存在正数和负数记录时，只要存在正数记录，该月可以作为首次实销月份；
- 从未出现正数实销的标准作品或业务形态，首次实销月份留空并进入异常确认；
- 标准作品上线时间取两种业务形态首次正数实销月份中的最早值。

`RB-WORK-LAUNCH-001` 已确认，不再是 `PENDING-DATA`。

### 3.2 逻辑对象影响

| 对象 | 字段或缓存 | 权威来源 | 重算触发 |
|---|---|---|---|
| `standard_work` | `launch_month_cache` | 有效收入事实 + 当前收入投影 + 正数实销规则 | 批次发布、撤销、映射投影切换、规则版本变化 |
| `work_business_form` | `first_positive_sale_month_cache` | 有效收入事实 + 当前收入投影 + 正数实销规则 | 同上 |
| 异常确认项 | 从未出现正数实销的作品或业务形态 | 计算结果 | 批次发布、撤销、映射投影切换 |

缓存必须记录计算所依据的收入投影版本和规则版本。不得使用数据库浮点计算金额符号。

对应：`REQ-WORK-003`、`REQ-WORK-004`、`AT-M1-022`、`AT-M1-023`。

## 4. 金额精度

### 4.1 已确认语义

财务确认使用 Excel 底层完整精度：

- 实销金额必须使用精确十进制语义保存和计算；
- 不按 Excel 显示位数舍入入库；
- 不允许使用 `float` / `double` 作为金额权威存储或对账计算；
- 严格对账、批次合计、月份合计、收入投影重建均使用同一精确十进制语义。

### 4.2 全量账单统计

真实账单统计结果：

| 指标 | 数值 |
|---|---:|
| 账单行数 | 192,899 |
| 账单月份范围 | 2017-06 至 2026-05 |
| 当前完整数据截止月份 | 2026-04 |
| 实销金额最大整数位 | 9 |
| 实销金额最大小数位 | 18 |
| 当前最大批次合计 | 253610173.052208979970873801 |
| Excel 显示值合计与底层精度合计差异 | 7.988191019963087199 |

### 4.3 DECIMAL/NUMERIC 候选

候选类型：`NUMERIC(32,18)` / `DECIMAL(32,18)`。

理由：

- 保留当前观测到的 18 位小数；
- 预留 14 位整数空间，远高于当前最大单行和批次合计的 9 位整数；
- 可同时用于单行权威金额、批次合计和严格对账，避免不同金额字段使用不同精度导致尾差；
- 溢出风险主要来自未来单行或批次金额超过 14 位整数，按当前 2.536 亿级批次合计有显著增长余量。

该精度仍为物理模型阶段候选，最终需结合目标数据库的 `NUMERIC/DECIMAL` 存储成本、索引策略和批量计算性能确认。

对应：`REQ-DATA-IMPORT-001`、`REQ-DATA-IMPORT-004`、`AT-M1-001`、`AT-M1-004`。

## 5. 同一 ID 多名称和多授权分类

### 5.1 已确认处理原则

真实账单中：

- 同一原始作品 ID 多名称冲突组：327 组；
- 同一原始作品 ID 多授权分类冲突组：18 组；

- 未确认冲突组继续阻断正式导入或正式收入投影；
- 运营确认后形成版本化映射，并应用于组内全部相关收入投影；
- 不自动选择出现次数最多或收入最高的名称作为正式结论。

### 5.2 冲突组展示字段

每个冲突组至少展示：

- 全部历史作品名称及各自记录数、月份范围和实销合计；
- 全部授权分类及各自记录数、月份范围和实销合计；
- 系统候选解释；
- 运营确认字段。

对应：`REQ-WORK-001`、`REQ-WORK-002`、`REQ-WORK-006`、`REQ-DQ-001`、`AT-M1-020`、`AT-M1-021`、`AT-M1-025`、`AT-M1-010`。

关联规则：作品 ID 数字主体优先，不得仅凭书名相似自动关联。

### 6.2 M1 基础信息覆盖缺口

以 3,099 部账单标准作品为基准：

| 缺口 | 数量 | 说明 |
|---|---:|---|
| 候选作者缺失 | 1,830 | 使用 `作者署名` / `作者原名` 作为候选字段统计 |
| 明确一级至三级分类缺失 | 3,099 | 台账无明确一级、二级、三级主分类字段 |
| 候选版权期限缺失 | 2,225 | 使用 `签订日期` + `到期时间` 作为候选期限统计 |
| 候选标签缺失 | 1,829 | 台账候选标签字段未覆盖这些标准作品 |

结论：数字版权台账不能单独覆盖 M1 基础信息需求。它可作为标准作品名称、候选作者、版权开始日期、版权到期日期和候选标签的来源之一，但不能直接冻结完整主数据。

### 6.3 仍需运营确认的台账事项

- 台账候选分类字段如何映射到正式一级、二级、三级分类；
- 台账候选标签字段如何进入辅助标签库和特殊属性标签库；
- 台账未覆盖的 1,829 部标准作品由何种来源补齐；
- 台账中 2 组同一标准作品候选版权期限差异如何处理；
- 纯数字和 `Y` 业务形态本次未发现候选版权期限反例，但仍需在后续新增台账中继续验证。

对应：`REQ-WORK-008` 至 `REQ-WORK-011`、`REQ-CLASS-001`、`REQ-CLASS-002`、`AT-M1-027` 至 `AT-M1-031`、`AT-M1-040`、`AT-M1-041`。

### 6.4 版权开始日期已确认语义

运营确认：

- 数字版权台账中的 `签订日期` 即授权或版权生效日期；
- `签订日期` 作为标准作品的版权开始日期；
- `到期时间` 作为标准作品的版权到期日期；
- 两种业务形态继续共享标准作品层版权期限；
- 同一标准作品出现多组不同 `签订日期` 或 `到期时间` 时，不自动选择，进入版权期限冲突确认；
- 台账未覆盖或日期缺失的标准作品继续进入基础信息补全。

版权开始日期的权威来源优先级为：

1. 已确认数字版权台账；
2. 运营补全文件；
3. 后续正式基础信息版本。

禁止根据作品上线时间、首次实销月份、文件创建时间或收入出现时间推算版权开始日期。版权期限冲突、缺失、补全和版本回退均必须保留确认记录和版本追溯。

## 9. 进入后续阶段的分层门槛

本轮将原“必须完成全部 2,364 个确认组后才能进入物理数据库设计”的口径拆分为三个门槛。不同门槛解决的问题不同，不能混用。

### 9.1 物理模型设计门槛

物理模型设计只要求业务语义和数据结构冻结，不要求全部作品级基础信息已经填写完成。至少包括：

1. 金额精度和金额计算语义；
2. 月份完整性和人工确认记录语义；
3. 首次正数实销规则；
4. 不可变收入事实与可重建映射投影关系；
5. 主数据版本机制、确认记录和回滚语义；
6. 版权开始日期和版权到期日期字段语义；
7. 分类树和标签库的数据结构。

当前已确认：数字版权台账 `签订日期` 对应版权开始日期，`到期时间` 对应版权到期日期；不得用作品上线时间、首次实销月份或文件创建时间推算版权开始日期。按现有 PRD，若分类树和标签库的数据结构继续保持冻结，则已满足开始 M1 物理模型设计的业务语义条件。

注意：该门槛只允许进入物理模型设计，不代表可以生成数据库迁移或导入正式数据。

### 9.2 首次正式数据迁移门槛

首次正式数据迁移必须满足：

1. 正式导入阻断冲突全部解决；
2. 金额、年月和作品 ID 关键字段异常已修正或已有确认处理；
3. 严格对账通过；
4. 映射版本、基础信息版本和回滚记录可落地。

首次正式数据迁移不要求全部标准作品基础信息都已补齐；未补齐部分继续作为 M2 前置缺口管理。

### 9.3 M2正式评估门槛

进入 M2 正式评估时，对应标准作品必须具备：

1. 标准作品名称；
2. 作者；
3. 一级至三级分类；
4. 版权开始日期；
5. 版权到期日期；
6. 必需标签；
7. 已确认的作品归并关系。

未满足上述条件的标准作品不得进入正式评估。系统不得根据出现频率、金额、日期长短或相似书名自动选择标准名称、作者、分类、标签或版权期限。

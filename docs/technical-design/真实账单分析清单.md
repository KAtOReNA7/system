# 真实账单分析清单

| 项目 | 内容 |
|---|---|
| 状态 | DRAFT |
| 日期 | 2026-06-20 |
| 目的 | 识别只有查看完整或接近完整真实账单后才能冻结的 M1 字段、规则和容量约束 |
| 禁止 | 不依据少量样本猜测阈值，不把候选结论直接写入正式规则 |

## 1. 分析原则

分析必须使用完整或接近完整的只读真实账单副本，覆盖不同年份、不同渠道、负数冲抵、渠道更名和历史分册。原始文件先按只读方式登记指纹，不修改源文件。所有分析脚本和结果只能运行在隔离测试环境，不得回写正式环境。

每个分析项输出五部分：观察到的数据事实、异常样本、候选规则、无法从账单单独确认的事项、建议验收样本。候选规则只有经过运营确认、形成验收用例并纳入规则版本后才能启用。

对应需求与验收：`REQ-DATA-IMPORT-001` 至 `REQ-DATA-IMPORT-007`、`REQ-DQ-001` 至 `REQ-DQ-003`、`REQ-WORK-001` 至 `REQ-WORK-011`、`REQ-CHANNEL-001`、`REQ-CLASS-001`、`REQ-CLASS-002`；`AT-M1-001` 至 `AT-M1-007`、`AT-M1-010` 至 `AT-M1-012`、`AT-M1-020` 至 `AT-M1-031`、`AT-M1-040`、`AT-M1-041`。

## 2. 文件与工作表结构

需要统计全部文件格式、扩展名、实际媒体类型、文件大小、工作表数量、工作表名称、有效数据起始行、表头位置、空白行、合并单元格、隐藏行列、公式单元格、错误单元格和文件损坏情况。

需要确认七个业务字段是否在所有年份和文件中使用相同名称与顺序，是否存在表头别名、多级表头、额外说明行、汇总行和小计行。额外列可以作为原始文件事实观察，但不得未经业务确认进入正式七字段模型。

输出应包括文件结构类型清单、每种类型的文件数量和记录规模、无法自动解析的样本、解析器候选适配范围，以及用于 `AT-M1-001`、`AT-M1-002`、`AT-M1-003` 的代表文件。

待确定字段或约束：允许的文件类型、表头识别规则、工作表选择规则、文件大小和记录数边界、分块大小、损坏和加密文件识别方式。

对应需求与验收：`REQ-DATA-IMPORT-001`、`REQ-DATA-IMPORT-002`、`REQ-DATA-IMPORT-003`；`AT-M1-001`、`AT-M1-002`、`AT-M1-003`。

## 3. 年月字段

需要枚举年月的原始单元格类型和展示格式，包括文本、日期、数字、公式结果、不同分隔符、仅年份、仅月份、空值和非法月份。需要检查是否存在账单月份与文件名称、工作表名称不一致的情况，以及单个文件覆盖连续月份还是离散月份。

输出应包括可无损解析格式、需要阻断的格式、月份分布、缺月和重复覆盖情况，并验证数据截止月份使用有效批次覆盖月份最大值是否能够正确表达现有数据。

待确定字段或约束：年月规范化规则、无法解析时的问题类型、批次覆盖月份表示方式和对缺月的提示方式。不能根据文件名自动修正账单行月份，除非形成明确规则并通过验收。

对应需求与验收：`REQ-DATA-IMPORT-001`、`REQ-DATA-IMPORT-005`、`REQ-DATA-IMPORT-006`；`AT-M1-001`、`AT-M1-005`、`AT-M1-006`。

## 4. 实销金额字段

需要统计实销金额的单元格类型、小数位数、最大值、最小值、零值数量、负值数量、正负分布、空值、非数字文本、千分位、货币符号、括号负数、科学计数法和公式结果。还要检查不同工具读取时是否出现二进制浮点尾差。

需要按文件、月份、渠道和作品分别求和，并使用精确十进制语义验证原始合计。不得使用人工调整金额消除尾差。

输出应包括所需金额精度候选、异常金额样本、零值和负值代表样本、最大批次合计范围，以及严格对账验收数据。金额精度在完整分布确认前不得猜测。

对应需求与验收：`REQ-DATA-IMPORT-001`、`REQ-DATA-IMPORT-004`、`REQ-DQ-002`；`AT-M1-001`、`AT-M1-004`、`AT-M1-011`。

## 5. 渠道 ID 与渠道名称

需要建立原始渠道 ID 到原始渠道名称的基数关系，检查一对一、一对多、多对一、空 ID、空名称、名称前后空格、大小写、全半角、公司后缀变化和明显更名情况。需要按月份观察 ID 与名称关系是否随时间变化，以判断别名有效时间能否从数据中确认。

需要输出渠道候选主表、别名候选、冲突组、无法唯一归属组和每组收入影响。深圳有咖与重庆有咖等已知案例应在真实数据中定位，但不能只凭示例建立全部规则。

待确定字段或约束：别名唯一键由渠道 ID、名称还是组合构成；名称规范化规则；有效时间范围；空 ID 或空名称是否阻断；一个 ID 对应多个名称时哪些属于更名、哪些属于冲突。

对应需求与验收：`REQ-CHANNEL-001`、`REQ-DQ-001`；`AT-M1-030`、`AT-M1-010`。

## 6. 原始财务作品 ID

需要对原始财务作品 ID 按原始单元格类型和原始文本进行枚举，统计纯数字、`Y+数字`、小写前缀、空格、前导零、全角字符、小数形式、科学计数法、超长数字、空值、其他前缀和混合字符。

必须验证电子表格读取过程是否已经损失前导零或长数字精度。分析时同时保留原始显示值和底层值，不能先转换为整数再统计。

输出应包括可直接接受格式、可通过明确规则规范化的格式、必须阻断的格式、每类数量和金额影响，以及 `12345`、`Y12345` 和异常样本的验收集合。

待确定字段或约束：大小写和空格是否可自动修正、前导零是否属于业务 ID、科学计数法能否无损还原、其他前缀的业务含义。未确认前不得静默规范化。

对应需求与验收：`REQ-WORK-001`、`REQ-WORK-002`、`REQ-DQ-001`；`AT-M1-020`、`AT-M1-021`、`AT-M1-010`。

## 7. 作品名称与授权分类

需要检查同一原始财务作品 ID 对应多个作品名称的情况，包括正常更名、错别字、空格差异、分册后缀和明显不同作品。需要检查同一标准作品数字主体下，纯数字和 `Y` 前缀记录的名称是否一致或可解释。

授权分类需要枚举全部原始值、空值、年份变化和与 ID 前缀的关系。当前业务形态由 ID 前缀决定，因此授权分类不得在未确认时反向覆盖业务形态，但可以作为冲突检查信号。

输出应包括名称冲突组、授权分类值域、前缀与授权分类交叉表、需要阻断的候选冲突和运营确认清单。

待确定字段或约束：作品名称规范化规则、标准作品名称选择来源、名称差异达到何种程度构成冲突，以及授权分类在质量检查中的具体作用。

对应需求与验收：`REQ-DATA-IMPORT-001`、`REQ-DQ-001`、`REQ-WORK-001`、`REQ-WORK-002`；`AT-M1-001`、`AT-M1-010`、`AT-M1-020`、`AT-M1-021`。

## 8. 重复记录与合法冲抵

需要在同一文件内按月份、渠道、作品 ID、作品名称和实销金额等组合统计完全相同行，并保留原始行位置。还需要比较去除作品名称差异、渠道名称差异或金额字段后的候选重复组，观察真实异常模式。

不同文件之间相同作品和月份不能自动判定为重复，但需要分析文件覆盖月份重叠、文件指纹不同但内容局部重叠的情况，为运营提供风险事实。

零值和负值不得作为重复删除依据。需要专门检查同月正负抵消、跨月冲抵、同额反向记录和连续调整模式，确认哪些属于合法账务事实。

输出应包括每种候选重复模式的记录数、金额影响、代表样本、误删风险、候选自动规则和验收用例。没有运营确认和历史验证时，候选模式只能生成问题，不能自动删除。

待确定字段或约束：完整重复模式、自动处理范围、规则自动化阈值和误判容忍标准。

对应需求与验收：`REQ-DATA-IMPORT-004`、`REQ-DQ-001`、`REQ-DQ-002`；`AT-M1-004`、`AT-M1-010`、`AT-M1-011`。

## 9. 历史分册与标准作品归并

需要寻找多个数字主体可能属于同一完整作品的样本，分析名称中的分册、卷、部、季等特征，并与已有作者、分类和版权信息交叉验证。仅凭名称相似不能自动归并。

需要检查拟归并 ID 的业务形态是否一致、是否已经分别产生大量收入、是否存在一个 ID 同时疑似属于多个主作品，以及旧 ID 在后续月份再次出现的频率。

输出应包括候选归并组、推荐主 ID 所依据的事实、冲突字段、金额和月份影响、运营确认结果，以及旧 ID 再次出现的验收样本。

待确定字段或约束：候选发现特征、主 ID 推荐顺序、名称或作者差异的阻断方式。最终归并必须由运营确认，分析不能自动建立正式映射。

对应需求与验收：`REQ-WORK-005`、`REQ-WORK-006`、`REQ-DQ-001`；`AT-M1-024`、`AT-M1-025`、`AT-M1-010`。

## 10. RB-WORK-LAUNCH-001 上线时间和业务形态首次实销月份

需要按标准作品数字主体分别计算纯数字和 `Y` 前缀的首次实销月份，再取二者最早值作为标准作品上线时间。需要统计两种业务形态同时存在的作品数量、首次实销月份差值和后来新增另一形态的典型样本。

已确认：标准作品和业务形态的首次实销月份，均取首次出现正数实销记录的月份。零金额和负金额不作为首次实销；同月存在正数和负数时，只要存在正数记录，该月可以作为首次实销月份。从未出现正数实销的作品，首次实销月份留空并进入异常确认。

输出应包括标准作品上线时间结果、业务形态首次实销月份结果、批次撤销后最早月份变化样本，以及用于 `AT-M1-022` 和 `AT-M1-023` 的验收集合。

对应需求与验收：`REQ-WORK-003`、`REQ-WORK-004`；`AT-M1-022`、`AT-M1-023`。

## 11. 文件指纹、重复上传与重新导入

需要比较历史文件是否存在文件名不同但内容完全相同、文件二进制不同但业务行完全相同、仅格式或工作表属性不同、仅增加说明行或重新排序的情况。

二进制文件指纹只能识别内容完全相同文件，无法自动识别业务内容相同但文件二进制不同的情况。分析应分别报告二进制重复和业务内容重复，不能混成一个未经确认的阻断规则。

需要准备“有效批次撤销后，原文件不修改直接重新导入”的业务确认材料。当前需求同时要求阻止相同文件重复上传和允许撤销后重新导入为新批次，完全相同内容的受控重导规则尚需确认。

对应需求与验收：`REQ-DATA-IMPORT-002`、`REQ-DATA-IMPORT-007`；`AT-M1-002`、`AT-M1-007`。

## 12. 文件规模与性能基线

需要统计文件大小、行数、工作表数、月份跨度和单文件金额范围的分位分布，并识别最大文件和最复杂文件。使用接近全量副本测量上传、解析、校验、问题生成、候选收入写入、批次激活、撤销和派生字段重算各阶段耗时及资源占用。

测试至少覆盖正常文件、最大文件、多文件全量任务、大量重复候选、大量渠道冲突和大量分册候选。页面关闭后任务必须继续，失败后不得出现部分正式结果。

输出应包括容量曲线、瓶颈、推荐分块策略候选、任务进度估算依据和最终性能验收建议。文件上限、分块大小、并发数和正式性能指标在测试完成前保持待定。

对应需求与验收：`REQ-DATA-IMPORT-003`、`REQ-DQ-003`、`REQ-PLATFORM-001`；`AT-M1-003`、`AT-M1-012`、`AT-M1-050`。

## 13. 分类、标签、作者与版权期限的数据来源缺口

当前七字段账单不包含作者、三级分类、标签、版权开始日期和版权到期日期。因此这些字段不能仅通过真实账单分析完成，必须识别额外的基础信息来源、补全模板或运营确认流程。

对于作者，需要确认标准名称、别名和同名作者消歧来源。对于分类和标签，需要结合全量作品分布形成最终分类树和初始标签库。对于版权期限，需要检查同一标准作品两种业务形态是否存在不同期限的真实反例；发现反例时按 PRD 阻断并提交业务确认，不能自行增加业务形态级版权字段。

输出应明确哪些字段可从账单直接获得、哪些需要补充数据源、哪些只能人工确认，以及缺失时是否阻断 M2。不得使用作品名称或授权分类猜测作者、完整三级分类或版权期限。

对应需求与验收：`REQ-WORK-002`、`REQ-WORK-010`、`REQ-WORK-011`、`REQ-CLASS-001`、`REQ-CLASS-002`；`AT-M1-021`、`AT-M1-029`、`AT-M1-031`、`AT-M1-040`、`AT-M1-041`。

## 14. 产品状态待定项

需要从全量月度收入中提取连续无收入、低收入、恢复收入和版权到期后尾部收入样本，为疑似下架和重新上架规则提供事实。分析只输出分布和案例，不直接确定观察周期、基本无收入金额、连续无收入月数或归零条件。

已下架和重新上架仍需运营确认。账单事实只能作为疑似状态和确认材料，不能未经确认生成最终状态规则。

对应需求与验收：`REQ-WORK-007`；`AT-M1-026`。

## 15. 数据质量处理量与退回规则

需要统计每个文件的问题数量、问题密度、问题类型数量、受影响金额和处理复杂度。通过真实运营试处理记录逐项确认所需时间，比较系统逐项处理与本地修正后重传的效率。

输出应提出“适合逐项确认”和“应整份退回”的候选判断因素，但不得仅凭主观设置固定数量阈值。最终规则需要运营检查、形成验收用例并版本化启用。

对应需求与验收：`REQ-DQ-003`；`AT-M1-012`。

## 16. 分析结果交付物

真实账单分析完成后应交付：文件结构清单、字段值域报告、金额精度报告、渠道映射候选和冲突表、作品 ID 格式报告、重复与冲抵模式报告、历史分册候选表、上线时间验证报告、容量与性能报告、基础信息来源缺口表、候选规则及误判样本、代表验收数据集。

每项候选结论必须标注对应 `REQ-*`、建议补充或更新的 `AT-M1-*`、数据样本范围、统计证据、运营确认状态、规则版本和启用记录。未经确认的结论继续保留为 `PENDING-DATA`。

## 17. 开始分析前检查

- 已获得只读真实数据副本，并确认不会回写正式环境；
- 测试凭证、邮件和任务与正式环境隔离；
- 原始文件已登记指纹并保持只读；
- 分析输出不包含不必要的敏感原始明细；
- 已确定运营确认人和技术分析负责人；
- 已准备候选规则、业务确认和验收用例的版本记录位置；
- 已确认分析不会恢复两个已删除的非统计金额字段。

# M1 应用开发数据库连通性测试计划 v0.1

状态：用于 local development、local test 和 CI test 的最小数据库连通性验证。

## 1. 测试目标

验证应用开发环境可以使用正式 `db/migrations/` 建立空库结构，并确认应用相关数据库角色的最小权限边界正确。

测试不导入真实数据，不连接正式数据库，不应用运营确认结果。

## 2. 测试前置条件

- PostgreSQL 16.x；
- Flyway OSS 10.21.0 或后续经项目确认的版本；
- `db/migrations/` 中存在 80 个正式 SQL 文件；
- 数据库为空；
- 预置或允许脚本创建以下角色：
  - `migration_owner`
  - `application_rw`
  - `application_ro`
  - `background_worker`
  - `backup_operator`

## 4. 最小连通性测试

| 编号 | 检查项 | 执行角色 | 预期 |
| --- | --- | --- | --- |
| DB-CONN-001 | `application_rw` 可连接 | `application_rw` | 成功 |
| DB-CONN-002 | `application_ro` 可连接 | `application_ro` | 成功 |
| DB-CONN-003 | `background_worker` 可连接 | `background_worker` | 成功 |
| DB-CONN-004 | 数据库时区 | `application_ro` | UTC |
| DB-CONN-005 | 正式视图可查询 | `application_ro` | 成功 |
| DB-CONN-006 | `system_state` 初始状态可读 | `migration_owner` | `schema_initialized` |
| DB-CONN-007 | `application_ro` 不能写业务表 | `application_ro` | 写入失败 |
| DB-CONN-008 | `application_rw` 不能直接修改 `income_fact` | `application_rw` | 修改失败 |
| DB-CONN-009 | `background_worker` 不能越权激活版本 | `background_worker` | 无激活函数执行权 |
| DB-CONN-010 | `SECURITY DEFINER` 固定 `search_path` | `migration_owner` | 全部固定 |

说明：`system_state` 直接读取当前由迁移/检查角色验证；应用运行期如需要暴露系统生命周期，应通过后续受控只读视图或接口设计，不应让普通业务接口使用 `migration_owner`。

## 5. 脚本验证

本轮脚本：

- `tools/dev-db/init-m1-dev-db.ps1`
- `tools/dev-db/check-m1-db-connectivity.ps1`

验证步骤：

```powershell
tools/dev-db/init-m1-dev-db.ps1 `
  -HostName 127.0.0.1 `
  -Port <local-test-port> `
  -AdminUser postgres `
  -DatabaseName m1_dev_smoke

tools/dev-db/check-m1-db-connectivity.ps1 `
  -HostName 127.0.0.1 `
  -Port <local-test-port> `
  -DatabaseName m1_dev_smoke
```

脚本通过标准：

- 初始化脚本退出码为 0；
- 连通性检查脚本退出码为 0；
- 输出 JSON 中 `status=ok`；
- 未读取 `data/`；
- 未导入任何真实数据；
- 未修改 `db/migrations/`。

## 6. 失败处理

如果任一检查失败：

- 不得导入真实数据绕过问题；
- 不得修改历史迁移 SQL；
- 不得使用 Flyway `repair` 掩盖 checksum 或执行失败；
- 应记录失败项，新增 forward-only 修复迁移或修正开发环境配置后重新验证。

## 7. 进入后端骨架开发判断

当以下条件同时满足时，允许进入 M1 应用最小后端骨架开发：

- 正式迁移目录仍为 80 个 SQL；
- 初始化脚本在本地隔离库通过；
- 连通性脚本在本地隔离库通过；
- 工作区未修改 `db/migrations/`；
- 未导入真实账单、台账或运营确认结果。

即使允许进入后端骨架开发，正式数据迁移仍保持禁止。

# M1 应用开发数据库初始化接入方案 v0.1

状态：允许用于应用开发前的本地/测试数据库结构初始化；仍禁止正式数据迁移和真实数据导入。

## 1. 目标与边界

本方案定义 M1 应用开发阶段如何使用已冻结的正式 Flyway 迁移目录 `db/migrations/` 建立开发/测试数据库结构，以及应用侧如何使用不同数据库角色。

本轮只允许：

- local development；
- local test；
- CI test；
- 空库；
- 纯合成数据；
- 脱敏 fixture。

本轮不包含：

- future staging；
- future production；
- 正式数据库连接；
- 真实账单导入；
- 数字版权台账导入；
- 运营确认结果自动应用；
- 正式 `mapping_version` 生成或应用。

## 2. 环境分层

| 环境 | 当前状态 | 允许的数据 | 迁移来源 | 说明 |
| --- | --- | --- | --- | --- |
| local development | 允许 | 空库、合成数据、脱敏 fixture | `db/migrations/` | 开发人员本机数据库 |
| local test | 允许 | 空库、合成数据 | `db/migrations/` | 本地自动化测试或 smoke test |
| CI test | 允许 | 空库、合成数据 | `db/migrations/` | CI 临时 PostgreSQL 服务 |
| future staging | 不在本轮范围 | 未授权 | 待后续门禁 | 不得在本轮配置 |
| future production | 不在本轮范围 | 未授权 | 待后续门禁 | 不得在本轮配置 |

禁止在代码、脚本或文档中写入正式库 URL、主机、端口、密码或凭据。

## 3. 角色使用边界

| 角色 | 应用开发阶段用途 | 禁止事项 |
| --- | --- | --- |
| `migration_owner` | 仅用于执行 Flyway 迁移和开发库结构初始化 | 应用运行不得使用 |
| `application_rw` | 普通应用读写账号 | 不得直接修改 `income_fact`；不得用于只读查询入口 |
| `application_ro` | 只读查询账号 | 不得写业务表 |
| `background_worker` | 后台任务账号；本轮仅允许 `/health/db` 用它读取 `system_state` 控制态 | 普通业务接口不得使用；不得越权激活版本 |
| `backup_operator` | 备份/恢复边界角色 | 不参与应用业务写入 |

初始化脚本不得保存真实密码。开发人员或 CI 如需密码认证，应通过环境变量、`.pgpass`、CI secret 或本地受控配置注入，且不得提交到 Git。

## 4. Flyway 初始化流程

唯一允许的迁移来源：

```text
db/migrations/
```

明确禁止的迁移来源：

```text
experiments/m1-flyway-candidate/migrations/
```

初始化流程：

1. 创建空 PostgreSQL 数据库；
2. 创建五类角色：
   - `migration_owner`
   - `application_rw`
   - `application_ro`
   - `background_worker`
   - `backup_operator`
3. 设置数据库时区为 UTC；
4. 使用 `migration_owner` 执行 Flyway `migrate`；
5. 执行 Flyway `info`；
6. 执行 Flyway `validate`；
7. 第二次执行 Flyway `migrate`，确认无重复执行；
8. 执行最小连通性检查。

Flyway 参数应包含：

```text
schemas=flyway_history,m1
defaultSchema=flyway_history
table=flyway_schema_history
createSchemas=true
cleanDisabled=true
placeholderReplacement=false
```

## 5. 本地初始化脚本

本轮提供 PowerShell 脚本候选：

- `tools/dev-db/init-m1-dev-db.ps1`
- `tools/dev-db/check-m1-db-connectivity.ps1`

示例：

```powershell
$env:PG_BIN = "<local-postgresql-bin>"

tools/dev-db/init-m1-dev-db.ps1 `
  -HostName 127.0.0.1 `
  -Port 55434 `
  -AdminUser postgres `
  -DatabaseName m1_dev

tools/dev-db/check-m1-db-connectivity.ps1 `
  -HostName 127.0.0.1 `
  -Port 55434 `
  -DatabaseName m1_dev
```

脚本安全约束：

- 只允许连接 `127.0.0.1`、`localhost` 或 `::1`；
- 初始化时拒绝覆盖已存在数据库；
- 校验 `db/migrations/` 中 SQL 数量必须为 80；
- 拒绝使用 `experiments` 目录作为迁移来源；
- 不保存密码；
- 不读取 `data/`；
- 不导入真实业务数据。

脚本会在 local/test/CI 开发库中额外授予最小元数据只读权限：

- `application_ro`、`background_worker` 可读取 `flyway_history.flyway_schema_history`；
- 该授权仅用于健康检查读取 schema version；
- 不授予业务表写权限；
- 不修改 `db/migrations/` 历史迁移。

## 6. 空库启动检查

应用开发前的空库启动检查至少包括：

- Flyway schema 当前版本为 `0060.290`；
- `m1.system_state` 初始状态为 `schema_initialized`；
- 5 个正式视图可查询；
- 数据库时区为 UTC；
- `application_rw`、`application_ro`、`background_worker` 可分别连接；
- `application_ro` 无写权限；
- `application_rw` 不可直接修改 `income_fact`；
- `background_worker` 不可执行版本激活函数。

`/health/db` 的连接角色拆分：

- 使用 `application_ro` 验证 UTC、Flyway 版本和 5 个正式视图；
- 使用 `background_worker` 读取 `m1.system_state` 控制态；
- 不使用 `migration_owner`；
- 不读取真实业务数据行；
- 不写入任何业务表。

## 7. 数据边界

本轮不得导入：

- 真实账单；
- 数字版权台账；
- 运营确认 Excel；
- 运营确认结果；
- 正式候选 `mapping_version`；
- 真实作品名；
- 真实渠道名；
- 真实作者；
- 真实金额明细；
- 真实版权日期。

如后续测试需要数据，只能使用纯合成数据或脱敏 fixture。合成数据不得从真实账单、台账或运营确认包中抽取。

## 8. 后续开发进入条件

完成本轮后，如初始化脚本和最小连通性测试均通过，允许进入：

```text
M1 应用最小后端骨架开发
```

但该许可仅限于：

- 空库结构；
- 合成数据；
- 本地/测试/CI 环境；
- 应用基础连接、健康检查、权限边界和最小后端骨架。

仍不得进入正式数据迁移、真实数据导入或运营确认结果自动应用。

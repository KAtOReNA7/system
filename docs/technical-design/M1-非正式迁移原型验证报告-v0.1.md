# M1 非正式迁移原型验证报告 v0.1

> 日期：2026-06-21  
> 结论：**通过（76/76）**  
> 性质：非生产实验，不是正式 Flyway migration history  
> 数据边界：只使用程序生成的合成数据；未读取或导入真实账单、数字版权台账、运营确认结果。

## 1. 结论

非正式 PostgreSQL 16 原型已在本地隔离实例真实执行。最终版本完成 48 张表、约束、函数、触发器、视图和权限创建，76 项验证全部通过，没有关键约束、生命周期、并发或权限失败。

原型验证过程中发现并修正了三项物理模型缺口：

1. 版本头冻结不能替代版本子表冻结；
2. `ready`/active 批次不能继续追加事实或修改严格对账结果；
3. 新分类 release、新标签 release 与基础信息版本需要一个原子切换函数。

修订后重新从空库执行，最终 76 项全部通过。结论允许下一步将原型整理为正式 Flyway SQL-only 迁移候选并审查，但本轮没有创建正式迁移文件，也不允许正式数据迁移。

### 4.1 生命周期

- `schema_initialized`、`master_data_initializing` 允许 0 active；
- `ready_for_bill_activation`、`operational` 拒绝 0 active；
- 四类版本的第二个 active 被部分唯一索引拒绝；
- bootstrap 四类版本与 ready 状态在同一事务建立；
- 首批批次激活同时退休 bootstrap mapping、激活真实 mapping 并进入 operational；
- 新批次激活、批次撤销、纯映射切换、基础信息切换通过；
- 新分类 release、新标签 release 与基础信息版本同事务切换通过；
- 提交前覆盖校验失败时，旧 active mapping 保持不变。

### 4.2 deferred trigger 与不变量

- `12345`、`Y12345` 作为不同完整原始 ID 保存，但都派生标准作品 ID `12345`；
- 业务形态分别派生为 `audio_copyright`、`audio_product`；
- 授权分类不能覆盖业务形态；
- 非法 ID 不能进入正式映射；
- 同一完整 ID 不能同时进入常规映射和历史分册映射；
- 历史分册 ID 不能通过不同 `business_form` 重复；
- 分类根节点不会利用 `parent_id IS NULL` 绕过唯一性；
- `income_fact` UPDATE/DELETE 被拒绝；active 批次不能追加事实；
- validated/active/retired 映射与基础信息快照不可变；
- active 分类和标签 release 的子项不可变；
- 新标准作品没有基础信息行时仍出现在缺口视图；
- `NUMERIC(32,18)` 保存并返回完整 18 位小数。

### 4.3 并发

两个实际映射切换事务争用同一个 advisory transaction lock：

- 第一个事务完成切换并持锁至提交；
- 第二个事务在 `lock_timeout=300ms` 下失败；
- 超时后数据库仍只有一个完整 active mapping，未出现批次/投影半切换。

### 4.4 权限

- `migration_owner` 可创建结构和执行受控切换；
- `application_rw` 不能直接修改 `income_fact` 或调用版本切换函数；
- `application_rw` 可调用被授权的作品 ID 解析函数；
- `application_ro` 可查询正式视图，不能查询基础事实表；
- `background_worker` 可构建候选，但直接激活版本被触发器拒绝；
- `backup_operator` 具备读取能力但无业务写权限；
- 7 个 SECURITY DEFINER 核心函数均固定 `search_path=pg_catalog,m1`。

## 8. 门禁结论

允许下一步将原型拆分、命名并整理为正式 Flyway SQL-only 迁移候选，随后进行独立代码审查和全新空库回归。

仍不允许：

- 把实验文件直接认定为已执行的正式迁移历史；
- 连接正式数据库或使用正式凭据；
- 导入真实账单、台账或运营确认结果；
- 自动应用尚未确认的运营结果；
- 绕过正式数据迁移门禁。

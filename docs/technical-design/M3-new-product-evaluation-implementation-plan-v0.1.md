# M3 新品评估实施方案 v0.1

生成日期：2026-06-28

本方案基于 `docs/prd/06-新品评估.md`、`docs/prd/00-governance/scope.md`、`docs/prd/20-evaluation/common-evaluation-rules.md`、M2 local candidate closeout 和 M3 parallel planning boundary。当前只进入 M3 parallel planning，不进入 M3 formal execution。

## 1. M3 定位

M3 新品评估面向上线前选题，目标是基于结构化材料、站内外信号、历史对标、作者排位、类别曲线和热度映射，形成五年预测、首年预测、评级、风险和可解释依据。

M3 与 M2 的关键差异：

| 项目 | M2 老品评估 | M3 新品评估 |
|---|---|---|
| 对象 | 已产生实销的标准作品 | 未产生实销的选题 |
| 核心输入 | 历史月度实销、版权、分类、状态 | 材料、作者、分类、字数、完结状态、外部热度、目标渠道、版权范围 |
| 预测范围 | 剩余版权期 | 五年累计、首年、第 1-5 年分布 |
| 对标方式 | 历史收入、生命周期和回测 | 精准历史对标、同作者修正、类别曲线、外部热度映射 |
| 正式结果 | 老品正式评估结果 | 新品选题评估结果 |
| 关联关系 | 标准作品为核心 | 选题后续只能正式关联一部标准作品 |

## 2. M3 当前阶段边界

| 阶段 | 是否允许 | 说明 |
|---|---|---|
| M3 parallel planning | 允许 | PRD 拆解、数据模型草案、API contract、页面方案、fixture/prototype、测试计划 |
| M3 local prototype | 待用户授权 | 可在 fixture/synthetic 数据上实现，不写正式结果 |
| M3 formal execution | 禁止 | 需要 M2 formal readiness、正式主数据、正式发布链路和用户单独授权 |

## 4. 阶段拆分

### M3-0 规划冻结

目标：冻结 M3 范围、非目标、数据来源、fixture 边界和正式门禁。

交付：

- M3 PRD v0.1。
- M3 API contract v0.1。
- M3 数据模型草案 v0.1。
- M3 页面方案 v0.1。
- M3 测试计划 v0.1。

### M3-1 选题库与输入 readiness

目标：建立选题对象、输入字段校验和缺口状态，不做正式评估。

核心字段：

- 书名、作者、来源、完整三级分类。
- 简介、字数、完结状态。
- 阅读/收藏/评分。
- 同名有声、影视动漫、站外热度。
- 目标渠道、版权期限范围、运营推荐理由。
- 出版物/原创网文分流标记。

验收：

- 缺字段时只能进入 readiness blocked 或 draft，不生成正式评估。
- 不上传或提交原始材料内容到公开仓库。

### M3-2 材料解析与结构化确认

目标：支持 Word/PPT/PDF/手动新建的结构化确认流程。

边界：

- 大文件按页、章节或幻灯片分块解析。
- 前台使用“原始材料片段 + 结构化字段”左右对照。
- 用户确认后，正式链路只保留结构化信息和文件元数据。
- 当前规划阶段不提交原始文件，不接入正式存储。

### M3-3 对标与作者排位

目标：实现新品预测的核心解释层。

规则：

- 精准对标不超过 3 部，1 部准确对标也可。
- 同作者作品不占对标名额。
- 系统与运营对标并列展示，冲突时同时保留。
- 买断收入剔除或单列，不混入实销对标。
- 历史收入做年代修正。
- 作者至少 3 部可测算有声收入作品时才启用作者排位。

### M3-4 预测引擎

目标：输出五年累计预测区间、五年基准、首年预测、第 1-5 年年度收入、渠道结构和解释。

预测组合：

- 精准历史对标。
- 同作者修正。
- 类别曲线。
- 热度映射。
- 运营对标修正。

输出边界：

- 方法差异大时输出区间和权重解释。
- 回测不足时采用基准柱 + 区间带。
- 总额为主，渠道结构为说明。

### M3-5 新品评级与风险

目标：基于五年预测形成评级，并展示调整原因。

规则：

- 评级使用 S+/S/A/B/C/D/E 或与 M2 前台等级保持一致的显示集合。
- 五年预测形成收入基础等级。
- 只有评级调整时展示基础等级和调整原因。
- 支撑因素最多 3 条，限制因素最多 3 条，风险最多 3 条。
- 不输出固定“是否建议开发”结论。
- 不设置资源投入等级。

### M3-6 选题与老品关联

目标：在作品产生实销后，把选题与标准作品安全关联。

规则：

- 一个选题只关联一部标准作品。
- 一部标准作品只正式关联一个选题。
- 只有作品产生实销后，运营才补充标准作品 ID。
- 系统检索已有老品并确认，不创建待收入记录。
- 纯数字和 Y 前缀按数字主体自动关联两种业务形态收入。

### M3-7 回测与校准入口

目标：为 M4 校准提供新品案例和回测结论。

回测节点：

- 上线前最后一次正式新品评估为基准。
- 首年、三年、五年形成正式结论。
- 结论：高于预测区间、落入预测区间、低于预测区间。
- 落入区间时标记靠近上限、接近基准或靠近下限。
- 重要偏差进入异常清单和通知中心。

## 5. 初始数据模型草案

| 对象 | 说明 |
|---|---|
| `m3_topic` | 选题主表，保存书名、作者、来源、分类、流程状态和创建信息 |
| `m3_topic_input_snapshot` | 结构化输入快照，保存字段版本和 readiness 结果 |
| `m3_material_file_metadata` | 原始材料元数据，不保存公开可提交原始内容 |
| `m3_material_chunk` | 本地/正式环境中的材料分块索引与结构化抽取结果 |
| `m3_comparator_candidate` | 系统/运营对标候选、相似点、差异点、排除原因 |
| `m3_author_rank_signal` | 作者内部排位和同排位参考信息 |
| `m3_external_signal_snapshot` | 外部热度、平台相对位置、采集时间和时效性 |
| `m3_forecast_attempt` | 新品评估尝试，遵守评估共同规则 |
| `m3_forecast_result` | 当前/历史/失效正式结果 |
| `m3_backtest_checkpoint` | 首年、三年、五年回测记录 |
| `m3_topic_work_link` | 选题与标准作品的一对一正式关联 |

本轮不写 migration。上述对象只作为实施方案草案。

## 6. API contract 草案

| API | 目的 | 当前阶段 |
|---|---|---|
| `GET /api/m3/topics` | 选题列表、筛选、排序、分页 | 规划 |
| `POST /api/m3/topics` | 手动新建选题 | 后续 fixture/prototype |
| `GET /api/m3/topics/:id` | 选题详情和输入 readiness | 规划 |
| `POST /api/m3/topics/:id/materials` | 上传材料元数据和解析任务 | 后续需正式授权 |
| `POST /api/m3/topics/:id/input-snapshots` | 结构化输入确认 | 后续 fixture/prototype |
| `GET /api/m3/topics/:id/comparators` | 对标候选与排除原因 | 规划 |
| `POST /api/m3/topics/:id/evaluation-tasks` | 受控评估任务 | formal 前禁用 |
| `GET /api/m3/evaluation-results/:id` | 评估结果详情 | 规划 |
| `GET /api/m3/backtests` | 回测列表和结论 | 规划 |

正式 write/export/task API 在 M3 formal 授权前保持禁用。

## 8. 测试计划草案

| 测试类别 | 覆盖点 |
|---|---|
| fixture 输入测试 | 必填字段、出版物/原创网文分流、readiness blocked |
| 材料解析测试 | Word/PPT/PDF 元数据、分块、结构化字段，不泄露原文 |
| 对标测试 | 1-3 部上限、同作者不占名额、候选与排除原因 |
| 作者排位测试 | 至少 3 部可测算作品才启用 |
| 预测测试 | 五年/首年/年度拆分/区间/渠道结构 |
| 评级测试 | 基础等级、调整原因、支撑/限制/风险数量上限 |
| 关联测试 | 一选题一标准作品，一标准作品一正式选题 |
| 回测测试 | 首年/三年/五年状态和偏差结论 |
| 安全测试 | 禁止真实原始材料、private 明细、连接串进入公开报告 |

## 9. M3 formal 前置门槛

M3 formal execution 启动前必须满足：

1. M2 readiness rerun 通过，或形成用户明确授权的 formal exception。
2. 版权到期、作者、版权开始、分类、标签、作品状态、音频版权状态形成闭环。
3. formal task/export/release/audit 机制完成。
4. M3 PRD、API contract、数据模型、页面方案和测试计划经用户确认。
5. 用户单独明确授权 M3 formal。

## 10. 推荐下一轮任务

下一轮优先执行：

1. `M3-0 PRD/API/Data/Page/Test contract pack`，只新增设计文档和 summary。
2. 不写 migration，不写正式 API，不写页面实现，不连接数据库。
3. 同步准备 M2 补表后 readiness rerun 的输入清单。
4. 等用户确认 M3 方案后，再进入 fixture/prototype 实现。

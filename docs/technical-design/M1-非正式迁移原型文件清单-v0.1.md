## 1. 用途边界

本清单用于下一轮生成“非正式迁移 SQL 原型”前的审查。非正式原型不得进入正式 `db/migrations/`，不得连接正式数据库，且不得导入真实账单、台账或运营确认结果。

## 3. 关键依赖顺序

1. `system_state` 必须早于任何 active 版本约束触发器。
2. `mapping_version` 必须早于批次激活字段、映射表和投影表。
3. `income_fact` 必须早于 `income_projection`。
4. `classification_release` 与 `tag_release` 必须早于基础信息版本。
5. `raw_work_id_mapping` 与 `historical_volume_mapping` 必须先建表，后绑定跨表 deferred constraint trigger。
6. 读取视图必须在全部基础表、索引和触发器之后创建。
7. 权限授予必须最后执行，避免中间对象遗漏授权或暴露写权限。

## 4. 原型必须覆盖的 v0.3 不变量

- 完整原始作品 ID：`12345` 与 `Y12345` 不相等；
- 标准作品 ID：二者可映射到 `12345`；
- 业务形态：纯数字为有声版权，Y 前缀为有声成品；
- 授权分类不得覆盖业务形态；
- 非法原始作品 ID 阻断并生成问题；
- 同版本常规映射和历史分册映射完整原始 ID 互斥；
- `system_state` 初始化阶段允许 0 active，`operational` 阶段要求各 1 active；
- 基础信息缺口视图以 `standard_work` 为左表。

## 5. 本轮结论

本轮只产出清单，不创建任何 SQL、迁移目录或 Flyway 配置。下一轮如获授权，可以在临时非正式目录或隔离环境中生成 SQL 原型，并通过 PostgreSQL 16 隔离实例验证。

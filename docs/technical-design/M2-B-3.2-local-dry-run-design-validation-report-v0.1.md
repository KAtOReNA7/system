## 6. failure recovery 验证

现有设计已定义关键停止条件：

| 失败场景 | 当前设计要求 | 验证结论 |
| --- | --- | --- |
| no-db readiness checker 失败 | 立即停止，不生成通过结论 | 已定义并由 B-3.1 测试覆盖 |
| 环境未授权 | 停止，不连接、不写入 | 已定义 |
| stage JSON 未授权 | 停止，不读取、不解析 | 已定义 |
| DB 连接配置未授权 | 停止，不读取、不连接 | 已定义 |
| migration 未授权 | 停止，不修改 `db/migrations/` | 已定义 |
| rollback 缺失 | 停止，不执行 dry-run 写入 | 已定义 |
| 真实数据泄露风险 | 停止，不输出明细、不提交私有内容 | 已定义 |
| 输出报告泄露风险 | 只允许公开摘要，不包含真实明细、金额、私有路径、连接配置或 stage JSON body | 已定义 |

验证结论：failure recovery 设计足以支撑下一步 M2-B-3.2a no-db report generator。实际 dry-run 写入前仍需实现级别的 rollback 检查和环境销毁策略。

## 7. rollback 验证

当前设计明确：

- no-db 阶段不需要 rollback；
- 一旦后续涉及本地 DB 写入，必须具备事务级 rollback 或环境级销毁策略；
- 候选 mapping 导入、非正式评估结果生成、验证性写入均不得在缺少 rollback 的情况下执行；
- formal / staging / production / shared DB 不允许进入 M2-B-3；
- local non-formal 结果不得发布为 formal current / historical / invalidated 结果。

验证结论：rollback 原则已定义；实现级 rollback 检查尚未实现，必须留到单独授权任务。

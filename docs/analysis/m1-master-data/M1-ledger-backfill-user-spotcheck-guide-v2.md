# M1 Ledger Backfill User Spotcheck Guide v2

本指南用于用户审核 M1 ledger backfill v2 的 80 条抽检样本。公开版本只描述口径、字段和门槛，不包含真实作品名、作者名、渠道名、台账原文或完整作品明细。

## 为什么只抽检 80 条

- v2 自动应用候选共 `7097` 条，直接逐条人工审核成本过高。
- 80 条样本覆盖高收入作品、版权日期、作者/书名、有声权利、中置信/边界候选，优先暴露会影响 M2 评估结果和业务判断的风险。
- 抽检结果只用于判断是否可以进入下一轮本地 staging apply；不会直接写正式主数据。

## 抽检覆盖字段

| 字段类型 | 审核重点 |
|---|---|
| 作品名 | 候选值是否与当前作品一致，是否存在分册、合集、修订版误判 |
| 作者 | 候选作者是否可信，是否存在笔名、多作者、译者/编者混入 |
| 版权开始日期 | 日期是否可作为版权期起点，是否只是签约日期或相对期限锚点 |
| 版权到期日期 | 是否存在自动续约、多日期冲突、无限期、相对期限未确认 |
| 出版社 | 出版主体是否可补基础信息 |
| 首发/出版日期 | 日期来源是否清晰，是否与作品出版事实一致 |
| 有声权利 | 是否确认为可制作/发行有声，是否存在限制或权利冲突 |
| 一级/二级分类候选 | 只作为候选复核，不自动生成三级分类 |

## 用户如何填写

用户只需要填写 `用户判断`，必要时填写 `用户修正值` 和 `用户备注`。

| 用户判断 | 使用场景 |
|---|---|
| 接受 | 候选值完全正确，可以作为后续本地 staging apply 候选 |
| 拒绝 | 候选值明显错误，不应应用 |
| 需修改 | 候选方向正确但值需要调整；必须填写用户修正值 |
| 不确定 | 暂无法判断；该项不会自动应用 |

## 达标门槛

进入“高置信候选本地 staging apply”的建议门槛：

- 用户抽检完成率 `>= 90%`。
- 高置信候选抽检接受率 `>= 95%`。
- 高收入样本错误数 `= 0`。
- 版权到期候选严重错误数 `= 0`。
- 作者/书名严重错误数 `= 0`。
- 有声权利严重错误数 `<= 1`。
- 所有“需修改”项都有用户修正值。
- “不确定”项不自动应用。
- 低/中置信项不自动应用。
- 冲突项不自动应用。

## 后续如何决定是否 apply

1. 用户填写极简中文抽检审核包。
2. Codex 运行 `npm run summarize:m1:ledger-spotcheck`。
3. 脚本输出 `waiting_for_user_spotcheck`、`needs_more_spotcheck`、`needs_rule_fix`、`not_ready` 或 `ready_for_local_staging_apply`。
4. 只有状态为 `ready_for_local_staging_apply`，且用户下一轮明确授权，才允许执行本地 staging apply。

本指南不进入 M3，不连接数据库，不写正式主数据，不提交 private Excel。
